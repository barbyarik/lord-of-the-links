# The Lord of the Links

Трекинг людей по пяти офисным камерам. Прототип присваивает глобальные ID видимым эпизодам, показывает движение на плане и позволяет сверить траекторию с исходными видео.

**WHERE** показывает людей, траектории и камеры. **WHY** показывает плотность и её пики. **HOW** находит общие участки маршрутов. Во всех представлениях одна шкала времени.

## Открыть демо

Скачайте `lol-demo-full.zip` из [материалов демо](https://github.com/barbyarik/lord-of-the-links/releases/tag/demo-v1) и запустите из корня репозитория. Для просмотра достаточно Python 3.10+ и браузера.

```sh
python3 -m src.web.server --dataset ~/Downloads/lol-demo-full.zip
```

Откройте [локальный интерфейс](http://127.0.0.1:8000). Сервер показывает готовые видео и предсказания. Профиль выбирается архивом. `lol-demo-full.zip` содержит 66 треков, `lol-demo-balanced.zip` — 70. Оба содержат результаты на 5 Гц и `tracks.csv` с ID, временем начала и конца и камерами каждого эпизода. `lol-demo-reference.zip` показывает эталон на 2 Гц.

## Как оценивали

С помощью агента разметили боксы людей и связи между треками на пяти камерах за 20 минут. Разметку визуально сверили и использовали как эталон для оценки. Если человека больше 60 секунд не видно ни на одной камере, следующее появление считается отдельным эпизодом. В эталоне 60 эпизодов.

| Метрика | Что показывает |
| --- | --- |
| **ID** | Сколько сквозных треков посчитал алгоритм. Сравниваем с 60 в эталоне. Разрыв одного трека увеличивает счёт, объединение разных людей уменьшает его. |
| **F1 сшивки** | Насколько точно алгоритм связывает наблюдения между камерами. Чем меньше ошибочных склеек и пропущенных связей, тем выше оценка. |
| **IDF1** | Насколько часто человек найден и получает правильный ID по ходу записи. Пропуски, лишние боксы и перескоки ID снижают оценку. |
| **HOTA** | Насколько хорошо алгоритм одновременно находит людей, обводит их рамками и сохраняет ID. Считает это при нескольких порогах совпадения рамок. |

## Результаты

| Профиль | Правил | ID | F1 сшивки | IDF1 | HOTA |
| --- | ---: | ---: | ---: | ---: | ---: |
| `core` | 0 | 163 | 63,86% | 65,93% | 50,94% |
| `greedy-add` | 3 | 72 | 63,72% | 71,15% | 54,21% |
| `greedy-remove` | 4 | 71 | 63,90% | 72,58% | 55,30% |
| `balanced` | 11 | 70 | **67,17%** | **75,67%** | **56,92%** |
| `full` | 15 | **66** | 66,56% | 75,28% | 56,82% |

`full` ближе к эталону по числу ID. `balanced` даёт более высокие метрики сшивки и меньше наблюдений под чужим ID. [Методика и эксперименты](docs/EXPERIMENTS.md)

## Как устроено

YOLO11m находит людей на сетке 5 Гц. ByteTrack ведёт локальные треки отдельно в каждой камере. CLIP-ReID описывает внешность по кропам. Локальный трек становится вершиной графа. LogReg оценивает пары треков по внешности, времени, соседству камер и доступной геометрии. Группы соединяются по среднему весу рёбер с проверками совместимости. Профиль выбирает, какие фильтры и доклейки включить. Экраны и зеркала определяются автоматически. Траектории на карте строятся из проекций нижней середины боксов на пол.

Для нового офиса задайте план, неподвижные якоря пола и соседство камер. Для новой записи с тех же камер задайте её синхронизацию. Веса и калибровку можно переиспользовать. Порог сшивки и LogReg можно проверить и при необходимости переобучить по размеченным переходам нового офиса. [Пайплайн](docs/ARCHITECTURE.md) · [Ограничения и перенос](docs/LIMITATIONS.md)

## Запустить на видео

Инференс запускается локально по записанным видео. Пример ниже использует CPU. При наличии подходящего устройства можно выбрать `mps` или `cuda:0`. Для обработки установите Python 3.14 и зависимости из `requirements.txt`. Подготовьте [веса моделей и исходные записи](docs/RUN.md).

```sh
python3.14 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt

python -m src run --profile full --recording config/recordings/hackathon.json \
  --models .local/models --device cpu --output dist/predictions.json \
  --video 1=.local/videos/camera_new_1.mkv --video 2=.local/videos/camera_new_2.mkv \
  --video 3=.local/videos/camera_new_3.mkv --video 4=.local/videos/camera_new_4.mkv \
  --video 5=.local/videos/camera_new_5.mkv
```

Команды `python -m src evaluate` и `python -m src build-demo` считают метрики и собирают новый пакет для интерфейса. Для быстрого повтора можно передать кэш боксов и эмбеддингов. [Команды и входы](docs/RUN.md) · [Контракт интерфейса](docs/DATA_CONTRACT.md)

## Репозиторий

- `src/` — инференс, оценка, экспорт и локальный интерфейс.
- `config/` — геометрия офиса, синхронизация записи и профили с именами и списками включённых правил.
- `artifacts/reference/` — эталонные боксы и треки для оценки.
- `artifacts/examples/` — небольшой синтетический пример формата предсказаний.
- `artifacts/test-results/` — сохранённые метрики профилей, результаты перебора правил и отчёт о воспроизведении.
- `docs/` — пайплайн, запуск, контракт, эксперименты и ограничения.
