# Контракт данных

## Входы прогона

Полный прогон получает исходные видео по камерам, интервал записи, калибровку офиса и временные якоря этой записи. Калибровка хранит геометрию камер относительно плана. Якорь связывает известный PTS исходного видео с показанием общих часов. По этим соответствиям кадры разных камер получают время на одной шкале. Номера кадров и PTS сохраняются для каждой камеры, поскольку их начало и частота могут различаться.

Повторный прогон может брать сырые детекции из кэша. Кэш содержит выбранные кадры с их временем, рамками и уверенностью детектора. ByteTrack и дальнейшие этапы выполняются для конкретного профиля. Например, `screens` меняет вход ByteTrack и может поменять состав локальных треков, даже если сырые детекции те же.

Кэш кропов хранится отдельно от детекций. Эмбеддинг относится к точному кропу исходного кадра, с учётом камеры, номера кадра и координат. При переключении профиля можно повторно использовать векторы неизменившихся кропов. Для новых кропов нужны исходные видео и веса ReID либо их точные векторы в кэше. Для свежих видео работают те же стадии с новой синхронизацией и заново вычисленными детекциями и эмбеддингами.

Эталон — вход этапа оценки. Ручные отметки рамок и связей задают наблюдаемые эпизоды, с новым эпизодом после паузы больше 60 с. У предсказаний и эталона собственные ID. Оценщик связывает их через рамки на проверенных кадрах.

## Канонический результат инференса

`predictions.json` содержит версию схемы, профиль, частоту, начало записи и список кадров.

| Поле | Тип | Смысл |
| --- | --- | --- |
| `schema_version` | целое `1` | Версия формата. |
| `profile` | строка | Выбранная конфигурация правил. |
| `sampling_hz` | число `5` | Частота отбора кадров. |
| `recording_start` | число | Начало общей шкалы времени в секундах, в том же формате, что `frames[].time`. |
| `frames[].camera` | целое | Номер камеры. |
| `frames[].frame_index` | целое | Индекс исходного кадра в этой камере. |
| `frames[].pts` | число | Временная отметка исходного видео в секундах. |
| `frames[].time` | число | Общие часы записи в секундах. |
| `frames[].tracks` | массив | Рамки треков в кадре. Обработанный кадр без рамок содержит пустой массив. |
| `tracks[].id` | строка | Локальный ID, включает камеру. |
| `tracks[].global_id` | строка | Глобальный ID эпизода. |
| `tracks[].box` | четыре числа | `[x_min, y_min, x_max, y_max]` в пикселях исходного изображения. |
| `tracks[].score` | число | Уверенность детекции рамки. |

Общие часы сериализуются в виде числовой шкалы epoch. Часы, показанные в видео, интерпретируются на этой шкале единообразно для всех камер. В интерфейсе их показываем как локальную отметку записи без суффикса часового пояса. Время на таймлайне в секундах — `time - recording_start`. Позиция в браузерном видео в секундах — `pts - first_source_pts`, где `first_source_pts` относится к выбранному медиаресурсу камеры.

Ключ кадра — пара `(camera, frame_index)`. У одного `global_id` на таком кадре остаётся максимум одна рамка. Тот же `global_id` может быть виден одновременно на нескольких камерах. Идентификаторы стабильны внутри пакета. Для сравнения разных профилей используйте соответствия по времени и рамкам.

[Пример `predictions.json`](../artifacts/examples/predictions.json) содержит четыре синтетических записи формата. На первом шаге `P001` виден на камерах 3 и 5. На втором камера 3 даёт пустой список рамок, а камера 5 продолжает тот же ID.

## Пакет интерфейса

Генератор читает `predictions.json`, калибровку, план и видео. Он строит папку, которую интерфейс открывает локально. Воспроизведение следует PTS видео, рамки и точки обновляются по фактическим наблюдениям сетки 5 Гц. Текущие точки, плотность и общие фрагменты маршрутов используют один набор ID выбранного пакета.

| Путь | Содержимое |
| --- | --- |
| `manifest.json` | Версия, тип источника `predictions`, профиль, `sampling_hz`, начало общих часов `common_t0`, список камер и информация о видео и размерах рамок. |
| `dataset.json` | Данные для браузера. Содержит `manifest`, кадры, наблюдения, сводку треков, интервалы видимости и проверку структуры. |
| `tracks.csv` | Сводка глобальных эпизодов с колонками `track_id`, `first_seen_s`, `last_seen_s`, `cameras`, `observation_count`. Время относительно начала записи, номера камер разделены пробелом. |
| `floor/plan.svg` | Общий план. |
| `floor/calibration.json` | Параметры проекции и допустимые зоны карты. |
| `floor/tracks-floor.json` | Точки по глобальному ID в координатах плана, время `t_s` и сведения о проекциях источников. `x` и `y` используются для карты, исходные координаты сохранены в `x_raw` и `y_raw` при сглаживании. |
| `videos/` | Медиаресурсы камер по относительным путям из манифеста. |

Интервалы видимости строятся для каждой пары ID–камера. Если камера перестала показывать рамку, её полоса на таймлайне прерывается. Глобальный ID при этом может продолжаться через другую камеру. Отсутствие надёжной проекции на пол также не мешает показать наблюдение на исходном видео.

Готовый пакет открывается командой `python -m src.web.server --dataset <bundle-dir>`. Интерфейс также принимает прежнюю папку или ZIP с эталонным контрактом на 2 Гц и папку плана через `--floor`. Такой источник сохраняет свою шкалу и маркируется отдельно от 5 Гц предиктов.
